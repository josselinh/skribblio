# Skribblio Tools — Project Guidelines

Skribblio Tools lets users build custom word lists (alone or collaboratively) and export them for Skribbl.io games. The whole app is private: every page requires a registered, logged-in user with a verified email address (the email is used for notifications).

## Architecture

- The front-end is a **Vue 3 + TypeScript single-page application** living in `resources/js`, built by Vite. It is not Inertia and not Blade: do not add Blade pages or Inertia.
- Laravel is a **JSON API** consumed by the SPA. Laravel serves a single view, `resources/views/app.blade.php`, for every front-end path (see `routes/web.php`).
- `routes/web.php` declares named SPA routes (`dashboard`, `login`, `password.reset`, `verification.notice`) because Laravel and Fortify generate redirects and email links to those names. Any other front-end path is handled by `Route::fallback`, which returns a JSON 404 for `api/*` or JSON requests.
- **Authentication**: Sanctum in SPA mode (session cookie + CSRF, `statefulApi()` in `bootstrap/app.php`) with **Fortify headless** (`'views' => false`). Fortify features enabled: registration, password reset, email verification, profile update, password update. Two-factor auth and passkeys are intentionally disabled.
- Fortify endpoints live at the root (`/login`, `/register`, `/logout`, `/forgot-password`, `/reset-password`, `/email/verification-notification`); the app's API lives under `/api`.
- After authentication, users land on `/dashboard` (Fortify `home` is `/dashboard`).

## Domain model

- **Word** (`words`): `name`, `word_group_id`, `created_by`. Belongs to exactly one group; the name is unique within its group, at most 32 characters (`Word::NAME_MAX_LENGTH`) and contains no comma, because Skribbl.io uses commas as separators. A word has no visibility of its own: it is visible to whoever can see its group.
- **WordGroup** (`word_groups`): `name`, `visibility`, `accepts_contributions` (default false), `created_by`. Has many words; belongs to many group collections through the `groups_collections` pivot (keys `group_collection_id`, `word_group_id`, plus `added_by`: who added the group, null once that user is deleted). The model is named `GroupCollection`, not `Collection`, to avoid confusion with Laravel's collection classes.
- **GroupCollection** (`group_collections`): `name`, `visibility`, `accepts_contributions` (default false), `created_by`. Belongs to many word groups through `groups_collections`. **A collection must always contain at least one group** (enforce it when creating a collection or detaching a group; the database cannot).
- **Favorites**: users favorite groups (`favorite_word_groups`) and collections (`favorite_group_collections`), with composite primary keys.
- `visibility` is the `App\Enums\Visibility` enum (`Public`: every logged-in user can see; `Private`: only the creator). Groups and collections share the `App\Models\Concerns\HasVisibility` trait (`creator()`, `isCreatedBy()`, `isVisibleTo()`, `visibleTo($user)` scope).
- Authorization lives in `app/Policies`:
    - Only the creator can update or delete a group or a collection.
    - **Contributions** ("Ouvert aux contributions", `AcceptsContributions` trait: `acceptsContributionFrom()`, `allowsChangingContributionOf()`): the creator always manages the content. While a group is open, anyone who can see it adds words and edits or deletes their own; while a collection is open, anyone who can see it adds groups and removes the ones they added. Once closed, only the creator changes the content, and earlier contributions are kept (reopening gives contributors their rights back). Name, visibility, the option and deletion stay with the creator.
    - A word can be edited or deleted by the creator of its group, or by its author while the group is open.
    - Whoever can add groups to a collection can attach any group they can see, including other users' public groups and their own private groups (hidden from the other viewers, who can request access).
    - Favoriting requires being able to see the item.
- A public collection may contain private groups. Other users must not see those groups: filter with `$groupCollection->wordGroups()->visibleTo($user)` and tell them that some groups are hidden.
- Deletions cascade: deleting a user deletes everything they created; deleting a group deletes its words and detaches it from collections; deleting a collection keeps its groups.
- Factories have `public()`, `private()`, `openToContributions()`, `closedToContributions()` and `createdBy($user)` states. `GroupCollectionFactory` attaches a group automatically when none was attached, to respect the "at least one group" rule.
- **Sharing private items** (`Shareable` trait, used with `HasVisibility`):
    - The creator gets a secret share link (`share_token`, generated on demand, regenerable to invalidate old links, never serialized). Opening `/share/groups/{token}` or `/share/collections/{token}` lets a user request access; the creator is emailed (`AccessRequested`), accepts or refuses (`AccessRequestDecided` email), and can revoke access later.
    - Requests live in `word_group_access_requests` / `group_collection_access_requests` (one row per item and requester, `AccessRequestStatus`: pending, accepted, refused; asking again after a refusal reopens it). Accepted requesters become members (`word_group_members` / `group_collection_members`).
    - Visibility = public, or creator, or member. A member of a private group can see it and add words. **A member of a collection also sees the private groups it contains, but only those created by the collection's creator** (consent rule: sharing a collection never exposes other people's groups). `WordGroup` overrides `isSharedWith()` / `orWhereSharedWith()` for this.
    - On a collection, a viewer can request access to all the groups hidden from them in one action; those requests carry `via_group_collection_id` and must never reveal the groups' names to the requester (not listed in "shared with me", refusal email without the name).
    - Policies: `share` (creator, private item only) and `manageAccess` (creator).

## Back-end conventions

- **Every primary key is a UUID**: models use `HasUuids`, migrations use `$table->uuid('id')->primary()` and `foreignUuid()` / `uuidMorphs()`. Never use `id()` or `foreignId()`.
- New business endpoints go inside the `auth:sanctum` + `verified` group of `routes/api.php`, in controllers under `app/Http/Controllers/Api`, validated by Form Requests (authorizing through the policy). Current endpoints:
    - `GET /api/word-groups`: the current user's own groups (12 per page, most recently updated first). `POST /api/word-groups` creates one; `GET`/`PATCH /api/word-groups/{id}` show/update one.
    - Favorites: `PUT`/`DELETE /api/word-groups/{id}/favorite` and `/api/group-collections/{id}/favorite` (idempotent; adding requires seeing the item, removing is always allowed). `GET /api/favorites/word-groups` and `GET /api/favorites/group-collections` list them (12 per page, most recently favorited first), including items that became private, flagged `is_accessible: false`.
    - Group and collection resources expose `is_favorite` when computed: use the `withIsFavorite($user)` scope on lists and `loadIsFavorite($user)` on a single model (`Favoritable` trait); never compute it per item.
    - Sharing: `GET`/`POST /api/{word-groups|group-collections}/{id}/share-link` (get / regenerate), `GET .../access` (pending requests and members), `DELETE .../members/{userId}`; `GET`/`POST /api/share/{word-groups|group-collections}/{token}[/access-request]` (invitation status: accessible, pending, refused, none); `GET /api/access-requests/received`, `POST /api/access-requests/{kind}/{id}/accept|refuse`; `GET /api/shared/word-groups|group-collections` (granted items and pending link requests, flagged with `access_status`); `POST /api/group-collections/{id}/hidden-word-groups/access-requests`.
    - `GET /api/search/word-groups` and `GET /api/search/group-collections` (`q`, `author=all|me|others`, `sort=recent|popular|largest|name`, `per_page` ≤ 24, `page`): paginated search, by name only, over what the user can see; names starting with `q` first, then the `sort` (`App\Enums\SearchSort`: most recently updated by default, most favorited, most words / groups, alphabetical), then most recently updated; results include `creator` and `words_count` / `word_groups_count`. Name search and author filtering are the `nameContains`, `orderByNameRelevance`, `orderBySearchSort` and `createdByAuthor` scopes of the `HasSearchableName` trait.
    - `GET /api/word-groups/search?q=`: up to 10 groups visible to the user whose name contains `q` (own groups first), with their `creator`; used by the group picker.
    - `GET /api/group-collections`: the current user's own collections (12 per page). `POST /api/group-collections` creates one with `word_group_ids` (at least one, each visible to the user), in a transaction.
    - `GET`/`PATCH /api/group-collections/{id}`: show (with the `word_groups` visible to the user and `hidden_word_groups_count`) / update a collection. `POST /api/group-collections/{id}/word-groups` (`word_group_id`) adds a group and records `added_by`, `DELETE /api/group-collections/{id}/word-groups/{wordGroupId}` removes one but refuses the last one (422). Create and update endpoints of groups and collections accept `accepts_contributions`. Both touch the collection's `updated_at`.
    - `GET`/`POST /api/word-groups/{id}/words`: list (20 per page, most recently added first) / add the words of a group. `POST` takes `names` (up to 500, split by the SPA from a comma- or newline-separated text): it is lenient, adds the valid words, skips those already in the group (as the database compares them, regardless of case and accents) and returns `{ data, skipped, invalid: [{ name, message }] }` (201 when a word was added, 200 otherwise); `AddWordForm` leaves the invalid ones in its textarea. `PATCH`/`DELETE /api/words/{id}` (shallow routes) rename/delete a word.
    - `POST /api/word-groups/{id}/duplicate` (`duplicate` policy: anyone who can see the group, members of a private group included): copies the group into a new group of the current user named "… (copie)", private and closed to contributions, with every word written by them (bulk insert in a transaction); favorites, members, share link and collections are not copied, and the copy keeps no link to the original. The group page shows a "Dupliquer" button (`can.duplicate`) and opens the copy.
    - `GET /api/word-groups/{id}/export` and `GET /api/group-collections/{id}/export`: every word (unpaginated, sorted by name, duplicates kept) of a group, or, for a collection, its groups visible to the user (sorted by name) each with its words, plus `hidden_word_groups_count` (never which groups), so that the SPA combines the chosen groups without reloading; allowed to anyone who can see the item.
- Resources expose a `can` object (e.g. `can.update`, `can.add_word`, `can.add_word_group`, and `can.remove_from_collection` on groups listed by a collection) computed from the policies, so the SPA shows or hides actions without duplicating authorization rules.
- A private group the user cannot see answers **404, not 403** (`Response::denyAsNotFound()` in the policy; Form Requests return `Gate::inspect(...)` to keep that status).
- Adding, renaming or deleting a word touches its group's `updated_at` (`#[Touches(['wordGroup'])]` on `Word`). Only `GET /api/user` is reachable by unverified users (the SPA needs it to know where to redirect).
- API responses always go through Eloquent API Resources (`app/Http/Resources`), with snake_case keys and ISO 8601 dates.
- The application locale is French (`APP_LOCALE=fr`). Translations come from `laravel-lang/common` (dev dependency) and are published in `lang/`; refresh them with `vendor/bin/sail artisan lang:update`. Add new user-facing strings in French.

## Front-end conventions

- Directory layout in `resources/js`: `pages/` (route components, `pages/auth/` for authentication, one sub-folder per domain such as `pages/word-groups/`), `components/` (reusable UI), `api/` (one module per API resource, e.g. `api/wordGroups.ts`, exposing typed functions), `stores/` (Pinia, setup syntax, for shared state such as the logged-in user), `composables/`, `router/`, `lib/` (HTTP client, formatting, labels), `types/`. Use the `@/` alias for imports.
- Authenticated pages are wrapped in `components/AppLayout.vue` (header + main container).
- Editing happens in place on the detail page (e.g. `EditableNameVisibility` turns the page title of a group or collection into an inline form, including the `ContributionsField` checkbox; `ContributionsBadge` shows "Contributions ouvertes" on pages and cards, `WordRow` edits or deletes a word inline with an in-page confirmation) rather than on separate edit pages. Data lists are tables; collections of items to open are cards.
- Paginated lists use Laravel's paginator (`PaginatedResponse<T>` in `types/api.ts`), keep the page in the URL query (`?page=N`, or a dedicated parameter such as `groups_page` when a page shows several lists) and render `components/PaginationNav.vue` (`page-param` prop). Load them with the `usePaginatedList(fetchPage, pageParam)` composable.
- The header (`AppLayout`) has an "Explorer" link and a search field, both leading to `/search` (`pages/search/SearchPage.vue`), whose filters (`q`, `type`, `author`, `sort`, `page`) live in the URL. Without `q`, the page is the "Explorer" catalogue for discovering what others share: the author filter defaults to `others` (to `all` with a search); default values stay out of the URL. The dashboard invites users with no group and no favorite to explore. Results are rendered with `SearchResultsSection` (typed `item` slot). Cards show "par X · N mots" through `CardMeta` when the resource includes `creator`/counts; use `creatorLabel()` from `@/lib/creator` to display "vous" for the current user.
- Group and collection cards are built on `ItemCard`: the whole card links to the item, the favorite star (`FavoriteButton`, optimistic, reverted on failure) sits outside the link, and an item with `is_accessible: false` is greyed out and not clickable while its star stays usable. Card lists use `CardListSection` (dashboard and search).
- The dashboard shows, in order: a "Créer un export" call to action, received access requests (only when there are some), favorite groups, favorite collections, own groups, own collections, groups shared with me, collections shared with me (page parameters `favorite_groups_page`, `favorite_collections_page`, `groups_page`, `collections_page`, `shared_groups_page`, `shared_collections_page`). Pending requests in the shared lists are greyed out like inaccessible favorites.
- User pages: clicking another user's name (card "par X", word author, access requester) opens `/users/{id}` (`pages/users/UserPage.vue`), listing that user's groups and collections visible to the current user (`GET /api/users/{id}`, `/api/users/{id}/word-groups`, `/api/users/{id}/group-collections`; never the email). The current user's own page redirects to the dashboard. Display names with `UserLink` (plain text for the current user). Cards use a stretched link on the title (`ItemCard`), so other links inside a card must sit above it (`relative z-10`).
- Profile: the header's `UserMenu` (initials, name, ▾) opens a menu with "Mon profil" (`/profile`) and "Se déconnecter". The profile page (`pages/ProfilePage.vue`) uses Fortify's `PUT /user/profile-information` (name, email; a new email un-verifies the account and sends a verification email) and `PUT /user/password` (requires `current_password`) through the auth store.
- **Skribbl.io export** (the core feature): `ExportPanel` ("Exporter pour Skribbl.io" on group and collection pages) loads the export endpoint on each opening (on a collection, after letting the user uncheck some of its groups, all checked by default) and shows the comma-separated list with a copy button, word and character counters, warnings (fewer than 10 words, more than 20,000 characters) and options: remove duplicates (case-insensitive, on by default), shuffle, and a random selection that fits in the character limit. Skribbl.io's limits and the list helpers live in `@/lib/skribbl`; formatting happens in the SPA, not in the API. The list itself is `WordListExport` (props `words`, `note`), reused by `ExportPanel` and by the "Créer un export" page (`/exports/new`, `pages/exports/CreateExportPage.vue`, linked from the top of the dashboard): the selection only holds groups: the user adds groups one by one, or all the visible groups of a collection at once (with a message saying how many were added, already selected or hidden), and removes any of them. Each group's words are loaded once through the export endpoints when it is added, and the SPA combines them. The selection can be saved as a new collection, which does not follow later changes. The selection is not kept in the URL.
- Sharing UI: `SharePanel` (link, copy, regenerate), `AccessManagement` (requests and members on a private item's page), `AccessRequestItem`, and `pages/share/SharePage.vue`. A logged-out user opening a share link is sent back to it after login or email verification (`@/lib/pendingRedirect`).
- Pick groups with `WordGroupSearch` (search dropdown over visible groups, emits `select`); `WordGroupPicker` wraps it with removable tags for forms. Both build on the generic `ItemSearch` (`search` function prop), also used to search collections.
- Show user-facing dates with `formatDateTime()` from `@/lib/format` and visibility labels from `@/lib/visibility`.
- To show a one-off status message on the next page, pass it in the router `state` (`router.push({ name, state: { status } })`); the target page reads it once with `consumeHistoryStatus()` from `@/lib/historyStatus` (on each route change when the page component is reused).
- Always call the server through the shared axios instance `http` from `@/lib/http` (it sends credentials and the XSRF token). Call `ensureCsrfCookie()` before guest-side state-changing auth requests.
- Every API payload has a TypeScript interface in `resources/js/types` that mirrors its API Resource (`models.ts` for resources, `api.ts` for response envelopes such as `ResourceResponse<T>`).
- Use the `useForm` composable for forms: it exposes `data`, `errors` (first Laravel validation message per field), `isProcessing`, `submit()` and `reset()`.
- Protect routes with `meta` in `router/index.ts`: `requiresVerified` (default for app pages), `requiresAuth` (logged in, verified or not), `guestOnly`.
- The UI is written in French. Styling uses Tailwind CSS v4 utility classes.
- Use `<script setup lang="ts">` with typed `defineProps<…>()` and `defineModel()`.

## Verification

- Front-end: `vendor/bin/sail npm run type-check` (vue-tsc); `vendor/bin/sail npm run build` type-checks and builds.
